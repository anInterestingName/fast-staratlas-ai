## 2. 摘要与目标

### 2.1 摘要

当前仓库只有 FastAPI 骨架，还不能调用大模型，也无法在不改业务代码的前提下切换供应商。本次要在单应用内提供可配置的模型档案、统一对话调用和最小编排能力，让调用方按档案名发起同步或 SSE 流式请求，并在主模型失败时按配置尝试备用档案。第一期联调与测试以 OpenAI GPT 为对象；模型名、超时、消息上限等档案级参数全部来自配置。本迭代不把配置接入数据库，但配置按独立、可落库的档案模型设计，后续改存储来源时不改调用契约。本迭代不提供结构化输出验证接口。

### 2.2 需求目标

1. 服务能通过配置接入至少一个 OpenAI 兼容的 GPT 模型，并支持为不同用途准备多个模型档案。
2. 调用方只按档案名使用模型，不需要知道供应商、接口地址或密钥。
3. 模型名、接口地址、超时、温度、消息条数上限、单条长度上限、默认档案和备用链均为配置，不得写死在业务代码中。
4. 系统能完成一次服务端编排后的模型调用：组装提示词、调用模型、解析助手文本，再以稳定契约返回。
5. 主档案失败时，系统按配置尝试备用档案；全部失败时返回明确错误，不把空结果当成成功。
6. 现有 `/health` 与 `/api/v1/demo` 行为保持不变；未配置模型密钥时，服务仍可启动，非 LLM 接口仍可用。
7. 本迭代配置来源为应用配置，不接入数据库；配置读取边界独立，后续可改为数据库而不改变对话/流式接口。

如存在明确指标，可补充：

| 指标 | 当前值 | 目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 不适用 | 不适用 | 不适用 | 本需求是平台基础能力，暂无业务转化或时延 SLA 指标 |

### 2.3 非目标

- 不引入独立 LLM 网关（如 LiteLLM Proxy、New API、OpenRouter 自建网关）。
- 不把各厂商官方 SDK/伙伴包作为默认接入方式；不为“可能用到的厂商”预先接入。
- 不实现多轮会话持久化、会话列表、历史消息落库。
- 不实现 RAG、向量库、知识库、Agent 工具循环、多步状态机业务。
- 不实现计费、配额、多 Key 负载均衡、虚拟密钥或团队预算。
- 不实现登录、认证、权限、审计、脱敏、租户隔离。当前仓库没有这些模块，本需求不引入，也不预留权限资源或动作。
- 不修改现有 Demo 内存存储的语义，也不把它当作 LLM 调用或模型配置的存储方案。
- 本迭代不把模型档案接入数据库，不创建配置表，不提供档案增删改 API。这不是否定后续配置落库，只是本迭代不实施存储。
- 不把模型名、超时、消息上限等可配置项写死为代码常量或写死在路由里。
- 不提供结构化输出验证接口，不开放调用方自定义 JSON Schema。待有真实业务结构后再单独立项。

### 3.2 范围内

- 使用独立的模型档案配置模型定义命名档案；至少支持 `fast`、`smart` 两个档案名，并支持指定默认档案。
- 第一期测试目标为 OpenAI GPT；默认通过 OpenAI 兼容协议在进程内访问，不部署独立网关。
- 档案级和全局级参数均可配置，至少包括：模型名、协议类型、接口地址、密钥、超时、温度、消息条数上限、单条长度上限、默认档案、备用链。
- 本迭代这些配置从应用配置（环境变量/Settings）读取，不接入数据库；读取边界独立于调用接口。
- 提供档案列表、同步对话、SSE 流式对话三类可观察 HTTP 能力。
- 对话请求只允许选择档案名和提交消息，不允许由调用方传入密钥、供应商、模型名覆盖或接口地址。
- 服务端执行单步编排：应用系统提示策略、调用模型、解析输出。
- 按配置对失败的主档案执行备用档案转移。
- 所有外部模型调用必须有有限超时，超时值来自配置；失败必须可区分。
- 密钥只来自配置，不出现在代码、示例文档、接口响应和常规日志中。
- 保持现有健康检查和 Demo 接口可用。

### 3.3 范围外

- 独立 LLM 网关、多 Key 负载均衡、统一账单：当前只有一个服务，后续若有多个服务再单独立项。
- 各厂商官方包作为默认接入、Anthropic/Gemini 原生能力：本迭代无已确认的原生能力需求。
- 视觉档案、Embeddings、重排序、语音：无已确认业务场景。
- 多步 LangGraph 业务、Agent、工具调用循环：当前没有真实多步业务，待有场景后单独立项。
- 会话记忆、聊天记录持久化、用户级历史：未要求持久化。
- 本迭代不把模型档案接入数据库、不创建配置表、不提供档案增删改 HTTP API。后续配置落库作为独立需求，需补数据库设计。
- 登录、认证、权限、限流、审计、脱敏：当前仓库无这些模块，本需求不引入，也不预留权限资源/动作。
- 结构化输出验证接口、固定示例 Schema、调用方自定义 JSON Schema：当前无真实业务结构，从本迭代移除，编号保留不复用。
- 修改 Demo CRUD 业务规则。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：服务已启动。模型密钥不是服务启动的前置条件。成功对话要求目标档案存在、已配置必要密钥，且外部模型服务可达。
- 触发入口：HTTP API（同步对话、SSE 流式对话、档案列表）。手工验证可通过 OpenAPI `/docs`。
- 最终结果：成功时返回助手文本或 SSE 增量事件；失败时返回明确错误，不写入任何业务存储。本需求不改变 Demo 数据，也不保存对话历史。

1. 调用方选择档案名（或省略以使用默认档案）并提交消息。
2. 系统校验请求；不合法则直接拒绝，不调用外部模型。
3. 系统解析档案；档案不存在或未就绪则直接拒绝，不调用外部模型。
4. 系统按服务端策略组装提示词，调用当前档案对应的模型。
5. 若当前档案失败且仍有备用档案，则切换后重试；否则返回依赖失败。
6. 成功时解析助手文本，按接口类型返回完整结果或 SSE 增量。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([开始]) --> B[调用方提交同步或流式对话请求]
    B --> C{请求参数合法?}
    C -- 否 --> D[返回校验错误]
    D --> Z([结束])
    C -- 是 --> E[解析目标模型档案]
    E --> F{档案存在且已就绪?}
    F -- 否 --> G[返回档案不可用错误]
    G --> Z
    F -- 是 --> H[按服务端策略组装提示词]
    H --> I[调用当前档案对应模型]
    I --> J{调用成功?}
    J -- 是 --> K[解析输出并按接口类型返回]
    K --> Z
    J -- 否 --> L{存在下一个已就绪备用档案?}
    L -- 是 --> M[切换到备用档案]
    M --> I
    L -- 否 --> N[返回明确依赖失败]
    N --> Z
~~~

档案发现流程：

~~~mermaid
flowchart TD
    A([开始]) --> B[调用方请求档案列表]
    B --> C[读取已配置的模型档案]
    C --> D[过滤或标记未就绪档案]
    D --> E[返回档案名、就绪状态和可公开字段]
    E --> Z([结束])
~~~

### 4.3 异常与替代流程

| 编号 | 触发条件 | 系统行为 | 用户提示 | 数据是否改变 |
| --- | --- | --- | --- | :---: |
| EX-001 | 请求体缺少必填消息、角色非法或超出长度/条数上限 | 不调用外部模型，返回校验错误 | 指出字段级错误 | 否 |
| EX-002 | 指定的档案名不存在 | 不调用外部模型，返回资源不存在或不可用错误 | 明确告知档案不存在 | 否 |
| EX-003 | 档案存在但缺少密钥或必填配置 | 不调用外部模型，返回档案未就绪错误 | 明确告知档案未就绪，不回显密钥 | 否 |
| EX-004 | 未指定档案且默认档案未配置或未就绪 | 同 EX-003 | 明确告知默认档案不可用 | 否 |
| EX-005 | 外部模型超时 | 记录档案名和失败类型，尝试下一个备用档案；无备用则返回依赖失败 | 明确为上游超时/不可用，不是空回复 | 否 |
| EX-006 | 外部模型返回密钥无效、限流或 5xx | 同 EX-005 | 明确为上游依赖失败，不回显上游密钥 | 否 |
| EX-007 | 全部备用档案均失败 | 返回依赖失败，不返回空助手内容作为成功 | 明确全部尝试失败 | 否 |
| EX-008 | 结构化输出无法解析为声明结构 | 本迭代不提供该能力，不适用 | 不适用 | 否 |
| EX-009 | 流式传输中途上游中断 | 结束 SSE 流并让调用方能区分“已完成”和“中途失败”；已发出的增量不回滚 | SSE 中带有失败结束事件，或连接以错误结束 | 否 |
| EX-010 | 未配置任何 LLM 密钥时访问健康检查或 Demo | 按原契约正常响应 | 与现网一致 | 否 |

## 5. 功能需求与验收标准

### 5.1 REQ-001 模型档案配置与发现

#### 5.1.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-008`
- 优先级：Must
- 触发入口：配置加载；档案列表 HTTP 接口
- 前置条件：无
- 输入：配置源中的档案定义；列表接口无业务必填入参
- 处理规则：
  1. 系统以命名档案管理模型，而不是让业务直接选择供应商或写死模型名。
  2. 本迭代至少支持档案名 `fast`、`smart`，并支持配置默认档案。
  3. 第一期测试供应商为 OpenAI GPT。`.env.example` 与文档示例使用 GPT，建议默认模型名为 `gpt-4o-mini`，但业务代码不得依赖这一字面量才能工作。
  4. 每个档案至少能配置下表字段；全局项对全部档案生效。建议默认值仅作为配置缺省，可被配置覆盖。
  5. 默认协议类型为 OpenAI 兼容；本迭代不要求同时启用多家官方 SDK。
  6. 缺少密钥或必填项的档案视为未就绪，不得被成功调用。
  7. 列表接口返回档案名、就绪状态、模型名等可公开字段，不返回密钥，不返回可还原密钥的内容。
  8. 未配置任何就绪档案时，列表可返回空列表或全部为未就绪，但不能导致应用启动失败。
  9. 修改配置中的模型名、超时或消息上限后，后续调用必须使用新值，无需改代码或改 HTTP 契约。
- 输出：可查询的档案清单；当前生效的配置供后续调用使用
- 限制：调用方不能通过请求体创建、修改档案或覆盖模型名；本迭代档案只从应用配置读取

档案与全局可配置项：

| 配置项 | 作用域 | 本迭代来源 | 就绪是否必填 | 建议缺省 | 说明 |
| --- | --- | --- | :---: | --- | --- |
| 档案名 | 档案 | 应用配置 | 是 | `fast` / `smart` | 调用入口，不是供应商名 |
| 协议类型 | 档案 | 应用配置 | 是 | OpenAI 兼容 | 第一期只要求这一种 |
| 模型名 | 档案 | 应用配置 | 是 | `gpt-4o-mini` | 第一期用 GPT 测试，必须可改 |
| 接口地址 | 档案 | 应用配置 | 否 | OpenAI 官方兼容地址 | 可指向兼容代理，本迭代不是独立网关产品 |
| 密钥 | 档案 | 应用配置 | 是 | 空 | 空则未就绪 |
| 超时秒数 | 档案 | 应用配置 | 是 | `60` | 必须有限；禁止无限等待 |
| 温度 | 档案 | 应用配置 | 否 | `0.2` | 未配置时用缺省 |
| 消息条数上限 | 档案或全局 | 应用配置 | 是 | `20` | 超出则校验失败 |
| 单条内容长度上限 | 档案或全局 | 应用配置 | 是 | `8000` | 字符上限；超出则校验失败 |
| 默认档案 | 全局 | 应用配置 | 是 | `smart` | 请求未指定档案时使用 |
| 备用链 | 全局 | 应用配置 | 否 | 空 | 按顺序失败转移 |

#### 5.1.2 验收标准

- `AC-001`：Given 配置了已就绪的 `smart` 档案，When 调用档案列表接口，Then 响应包含 `smart` 且标记为就绪，并且不含密钥字段。
- `AC-002`：Given 某档案缺少密钥，When 调用档案列表接口，Then 该档案要么不作为可调用就绪项，要么明确标记为未就绪，且仍不返回密钥。
- `AC-003`：Given 未配置任何 LLM 密钥，When 启动服务并访问 `/health`，Then 服务可启动且健康检查成功。
- `AC-025`：Given `smart` 档案模型名从 `gpt-4o-mini` 改为另一合法 GPT 模型名且密钥有效，When 再次发起同样的对话请求，Then 系统按新模型名调用，调用方无需改路径或字段。
- `AC-026`：Given 将消息条数上限配置为 `1`，When 提交两条用户消息，Then 返回校验错误且不调用外部模型。

### 5.2 REQ-002 供应商隔离与接入约束

#### 5.2.1 需求说明

- 关联用户故事：`US-001`、`US-007`
- 优先级：Must
- 触发入口：全部 LLM HTTP 接口
- 前置条件：无
- 输入：档案名、消息
- 处理规则：
  1. HTTP 接口和业务入口只接受档案名，不接受供应商名、接口地址或密钥作为调用目标。
  2. 切换某档案的供应商、模型名或地址，只应修改配置，不应要求调用方改请求契约，也不应改业务代码中的模型字面量。
  3. 本迭代默认使用 OpenAI 兼容协议在进程内访问 GPT；第一期测试对象为 OpenAI GPT。
  4. 本迭代不引入独立 LLM 网关作为运行时依赖。
  5. 现有 Demo 和健康检查接口不得依赖特定供应商。
- 输出：同一套同步/流式对话契约可指向不同供应商
- 限制：请求中出现密钥、接口地址或供应商覆盖字段时应拒绝，而不是接受并改写服务配置

#### 5.2.2 验收标准

- `AC-004`：Given 合法对话请求，When 请求体只提供档案名和消息，Then 系统能完成调用且响应中不出现密钥。
- `AC-005`：Given 调用方在请求中携带密钥、接口地址、模型名或供应商覆盖字段，When 提交对话请求，Then 系统拒绝该请求且不调用外部模型。
- `AC-006`：Given `smart` 档案从供应商 A 的兼容接口改为供应商 B 的兼容接口且调用契约不变，When 再次发起同样的对话请求，Then 仍使用同一 HTTP 契约，不要求调用方改字段名或路径。

### 5.3 REQ-003 同步对话调用

#### 5.3.1 需求说明

- 关联用户故事：`US-003`
- 优先级：Must
- 触发入口：同步对话 HTTP 接口
- 前置条件：目标档案已就绪，或存在已就绪备用档案
- 输入：可选档案名、消息列表（角色与内容）。省略档案名时使用默认档案
- 处理规则：
  1. 消息角色仅允许系统已声明的集合，至少包括 `user`，以及服务端编排所需的 `system`/`assistant` 处理方式。
  2. 系统在调用模型前执行服务端提示词组装，不得把请求原样当作供应商协议透明转发。
  3. 成功时返回完整助手文本；若上游提供用量信息，则一并返回 token 用量。
  4. 响应应能让调用方知道实际使用的档案名；不要求暴露供应商内部账号。
  5. 失败时使用明确错误，不返回 2xx 空内容。
- 输出：助手完整回复及档案使用信息
- 限制：消息条数和单条长度必须有上限，上限来自配置而不是代码常量；超出则校验失败。建议缺省见 REQ-001 配置表。

#### 5.3.2 验收标准

- `AC-007`：Given 默认档案已就绪，When 提交一条合法用户消息且不指定档案名，Then 返回成功响应，包含非空助手文本和实际使用的档案名。
- `AC-008`：Given 指定 `fast` 档案已就绪，When 提交合法对话请求，Then 实际使用档案为 `fast`。
- `AC-009`：Given 消息列表为空、角色非法或超出上限，When 提交同步对话请求，Then 返回校验错误且不调用外部模型。

### 5.4 REQ-004 流式对话调用

#### 5.4.1 需求说明

- 关联用户故事：`US-004`
- 优先级：Must
- 触发入口：流式对话 HTTP 接口或同步接口的流式模式
- 前置条件：同 REQ-003
- 输入：同 REQ-003
- 处理规则：
  1. 调用方必须能在生成完成前增量看到助手文本。
  2. 流式与同步使用同一套档案解析、编排和失败转移规则。
  3. 流必须有明确结束信号；正常结束与中途失败可区分。
  4. 传输协议固定为 SSE（Server-Sent Events）。成功进入生成后的响应 `Content-Type` 为 `text/event-stream`。
  5. 本迭代不使用 NDJSON、WebSocket 或其他流协议。SSE 事件字段由详细设计给出，但必须能表达文本增量、正常完成和失败结束。
  6. 请求校验失败时不得先按 SSE 成功流开始再报错；应在建立生成流之前返回普通 HTTP 错误。
- 输出：SSE 助手文本增量事件，以及可观察的完成或失败结束
- 限制：与同步对话相同的消息上限；不允许在流式请求中覆盖供应商配置；SSE 不是档案级可配置项

#### 5.4.2 验收标准

- `AC-010`：Given 目标档案已就绪，When 发起流式对话，Then 响应 `Content-Type` 为 `text/event-stream`，且调用方可在最终结束前收到至少一次非空增量文本。
- `AC-011`：Given 流式请求参数非法，When 发起流式对话，Then 在建立 SSE 生成流之前返回校验错误，且不调用外部模型。
- `AC-012`：Given 上游在流式过程中失败且无可用备用档案，When 消费该 SSE 流，Then 调用方可区分该次调用未正常完成。

### 5.6 REQ-006 备用档案失败转移

#### 5.6.1 需求说明

- 关联用户故事：`US-006`
- 优先级：Must
- 触发入口：同步和流式对话
- 前置条件：配置了主档案和至少一个已就绪备用档案
- 输入：同对应调用接口；备用顺序来自配置，不由单次请求指定
- 处理规则：
  1. 主档案因超时、上游密钥无效、限流或 5xx 失败时，按配置顺序尝试下一个已就绪备用档案。
  2. 未就绪备用档案跳过，不算成功。
  3. 任一档案成功即返回成功，并标明实际使用的档案。
  4. 全部失败则返回依赖失败，不返回空成功。
  5. 请求校验失败、档案不存在不属于失败转移范围，不因此改打其他档案。
- 输出：成功结果或最终依赖失败
- 限制：单次请求的转移次数和顺序只来自配置；调用方不能在请求中指定任意备用链

#### 5.6.2 验收标准

- `AC-015`：Given 主档案必定失败且备用档案已就绪，When 发起同步对话，Then 返回成功，且实际使用档案为备用档案。
- `AC-016`：Given 主档案和备用档案均失败，When 发起同步对话，Then 返回明确依赖失败，响应不是带空文本的成功。
- `AC-017`：Given 请求校验失败，When 发起对话，Then 不进行失败转移，也不调用任何外部模型。

### 5.7 REQ-007 服务端单步编排

#### 5.7.1 需求说明

- 关联用户故事：`US-007`
- 优先级：Must
- 触发入口：同步和流式对话
- 前置条件：目标档案可调用
- 输入：调用方消息
- 处理规则：
  1. 系统必须在服务端组装提示词，至少应用一条服务端系统策略（例如输出约束），再调用模型。
  2. 系统必须解析模型输出后再对外返回；同步返回完整助手文本，流式返回增量文本。
  3. 本迭代编排范围限于单步：一次组装、一次或多次因失败转移产生的模型调用、一次文本解析。
  4. 不在本迭代交付结构化对象输出、多步状态机、工具循环或可恢复会话。
- 输出：经过编排和解析的业务响应
- 限制：调用方不能关闭服务端系统策略以把服务变成纯代理；如需覆盖用户 system 消息，必须明确优先级且不得破坏安全底线

#### 5.7.2 验收标准

- `AC-018`：Given 合法对话请求，When 调用成功，Then 实际发送给模型的内容包含服务端系统策略，而不仅是调用方原文透传。
- `AC-019`：不适用。原结构化输出解析验收已随 REQ-005 移出本迭代。

### 5.8 REQ-008 超时与依赖失败可见性

#### 5.8.1 需求说明

- 关联用户故事：`US-003`、`US-006`
- 优先级：Must
- 触发入口：所有会调用外部模型的接口
- 前置条件：目标档案指向某个外部模型服务
- 输入：合法请求
- 处理规则：
  1. 每个档案必须有有限超时，禁止无限等待。超时秒数来自配置，建议缺省 `60`。
  2. 超时、连接失败、上游 4xx/5xx 必须作为依赖失败进入失败转移或最终错误。
  3. 禁止把空字符串、空对象或“看起来没数据”当成成功业务结果。
  4. 对外错误不包含密钥、完整上游鉴权头或完整敏感请求体。
- 输出：成功业务结果，或可区分的校验失败 / 档案不可用 / 依赖失败
- 限制：超时必须可配置；调用方不能在请求中把超时设为无限

#### 5.8.2 验收标准

- `AC-020`：Given 上游超过该档案超时仍未返回，When 发起同步对话且无可用备用，Then 请求以依赖失败结束，不一直挂起至客户端自行断开后仍被当成成功。
- `AC-021`：Given 上游返回错误或空失败，When 系统结束本次调用，Then 调用方能区分这不是一次成功对话。

### 5.9 REQ-009 密钥与日志安全底线

#### 5.9.1 需求说明

- 关联用户故事：`US-001`
- 优先级：Must
- 触发入口：配置加载、全部 LLM 接口、日志输出
- 前置条件：无
- 输入：档案密钥及调用请求
- 处理规则：
  1. 密钥只允许来自环境变量或密钥管理配置，不得写入仓库代码、`.env.example` 实值或需求/设计正文。
  2. 接口响应不得返回密钥、鉴权头。
  3. 常规日志可记录档案名、失败类型、时延、用量，不得记录密钥、连接串和完整敏感请求体。
  4. 本需求不建设审计模块或脱敏模块。
- 输出：不含密钥的响应与日志
- 限制：`.env.example` 只给空占位或假示例，不给真实密钥

#### 5.9.2 验收标准

- `AC-022`：Given 任意成功或失败的 LLM 接口响应，When 检查响应体，Then 不包含 API Key 或可还原的密钥。
- `AC-023`：Given 一次失败的上游调用，When 检查常规日志，Then 能看到档案名或失败类型，但不能看到密钥全文。
- `AC-024`：Given 查看 `.env.example`，When 检查 LLM 相关项，Then 只有变量名和空/占位值，没有真实密钥。

### 5.10 REQ-010 配置来源隔离与可落库方向

#### 5.10.1 需求说明

- 关联用户故事：`US-008`
- 优先级：Must
- 触发入口：配置加载、档案列表、全部 LLM 调用
- 前置条件：无
- 输入：当前配置源中的档案与全局项
- 处理规则：
  1. 模型档案是独立配置模型，不是写在路由或编排逻辑里的常量集合。
  2. 对话和流式接口只消费“已解析的档案”，不直接绑定某一种存储实现。
  3. 本迭代配置来源为应用配置（环境变量/Settings），不接入数据库，不创建 LLM 配置表，不提供档案写入 API。
  4. 后续若将同一档案模型落入数据库，列表和调用 HTTP 契约必须保持不变；那是独立需求，需补数据库设计。
  5. 本迭代不为尚未实施的数据库预建空表、占位列或空 CRUD 接口。
  6. 第一期联调对象为 GPT；更换模型名或兼容地址只改配置。
- 输出：进程内可用的档案视图，供列表和调用使用
- 限制：本迭代没有配置持久化副作用；重复启动以当时应用配置为准

#### 5.10.2 验收标准

- `AC-027`：Given 本迭代交付范围，When 检查接口与数据存储，Then 不存在模型档案的数据库表，也不存在创建/更新/删除档案的 HTTP API。
- `AC-028`：Given 仅通过应用配置提供 GPT 档案（示例模型名 `gpt-4o-mini`）且密钥有效，When 调用同步对话，Then 可以完成一次成功调用。
- `AC-029`：Given 档案列表或对话请求，When 检查 HTTP 入参和出参，Then 调用方只使用档案名等业务字段，不出现配置存储来源（环境变量/数据库）标识，也不出现为未来落库预留的空字段。

### 6.2 状态与迁移

不适用。本需求不引入会话、工单或可持久化业务实体；每次调用都是无状态的请求-响应。档案只有配置意义上的“就绪 / 未就绪”，不是用户可迁移的业务状态。后续若配置落库，档案仍是全局配置资源，不在本迭代定义状态机。

## 7. 认证与访问边界

不涉及。

当前仓库没有认证、权限、角色或租户模块。本需求不增加登录、Token 校验、权限项、归属字段或后续权限预留。接口不做身份区分；拒绝原因只来自参数校验、档案未就绪或上游依赖失败。

审计、脱敏：不涉及。本次未要求审计或脱敏能力；仅遵守不采集、不记录、不输出密钥和完整敏感请求体的通用安全底线。
